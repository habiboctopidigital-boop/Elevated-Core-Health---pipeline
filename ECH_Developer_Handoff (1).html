3Pipeline board & stage gating

7-stage Kanban board EXISTS

Keep the current stages exactly: Onboarding → Visit Complete → Post-Visit Docs → Chart Signed → Sent to Billing → Payment Posted → Reconciled. Cards show name, contact, appointment, assignee, source, and checklist progress.

Stage-advance gating NEW

This is the core rule from the call: a card cannot move to the next stage until every REQUIRED checklist item for the current stage is complete. Donna's words — "it won't be able to push across to the next level until Jude clears all of that."

Behavior
"Move Next" button is disabled/blocked while any required item is unchecked. Show which items are blocking.
Scope
Each stage defines its own required vs. optional items (see §4).
Log
Every stage move and checklist toggle writes to the activity log (already the pattern).

Provider ↔ VA hand-back loop NEW

The flow isn't strictly one-directional. Model these hand-offs explicitly:

  • VA clears all Onboarding items → hands to Donna (provider) to see the patient.
  • After the visit, Donna prescribes → hands back to VA for Post-Visit Docs (instruction letter, medication pamphlets, labs).
  • VA finishes post-visit → hands back to Donna to sign the chart → Chart Signed.
  • Signed → Billing submits claim → marks billing done.

4Per-stage SOP + checklists

Embedded SOP per stage NEW

Donna: "As a list of things that the VA is supposed to do that comes from the SOP, I want that to be on it… if I have a new VA, I don't have to tell them everything." Each stage shows its SOP text inside the patient card/modal, editable by admin in the Checklist Manager.

Onboarding checklist (required unless noted) CHANGE

Replace the current placeholder items ("new check list", etc.) with the real onboarding steps Donna listed:

  • Intake forms sent (Optimantra portal) — required
  • Intake forms completed & clear — required
  • Insurance information received & verified — required
  • VOB / eligibility passed (coverage active, copay known) — required
  • Credit card on file — required
  • PHQ-9 / GAD-7 received — optional
  • ADHD patients: e-forms cleared + controlled-substance protocol acknowledged — optional (conditional)
  • Appointment confirmed with patient — required

Other stage checklists EXISTS + CHANGE

Post-Visit Docs: patient instruction letter sent (req), medication pamphlet sent, labs sent. Chart Signed: Optimantra note signed (req), clawback check passed CPT/ICD-10 (req) — these already exist as defaults, keep them. Sent to Billing: claim submitted (req). Payment: payment posted (req). Reconciled: reconciled & closed (req).

5VOB / eligibility step NEW

Before the insurance/onboarding steps proceed, run VOB to decide whether ECH can take the patient, and surface the result on the card so Jude/Donna don't have to open Optimantra separately.

On card
VOB status chip: Passed ✓ / Needs review ✕ / Pending / N-A (self-pay). Show coverage, payer, member ID, copay.
Gating
VOB pass is a required onboarding item — a failed/incomplete VOB blocks advancement and routes to a VA for a manual call.
Behavioral-health caveat
Some payers don't return full BH benefit detail (session limits, prior-auth) via the automated feed. Treat "incomplete" as a review case, not a pass.
Self-pay
Skip VOB; require card-on-file collection instead.

6Flag & response workflow EXISTS

Already present and matches what Donna wants: a VA can flag a patient with a question ("can I pick up this patient?"), and Donna responds to clear it ("yes sure, no worries"). Keep this. Make sure an open flag is visible on the card and on the dashboard KPI ("Flagged for Admin"), and that only the admin can clear it.

7Work Queue — source / KPI view NEW

Donna asked to view everything "via a spreadsheet" too — one row per patient showing where the lead came from so she can track KPIs and build mailing lists. This is a table view alongside the board.

  • Columns: patient, source (KPI), platform, appointment, stage, assigned VA, insurance, VOB result, copay, phone.
  • Filter by source; export to CSV.
  • Same data as the board — just a different lens.

8Lead CRM NEW

A lightweight lead pipeline, separate from the patient board, so inquiries (chatbot, phone, ads, referrals) don't get lost before they book. Optimantra is for patients under care — not leads.

Stages
New Lead → Contacted → Booked → Converted to Patient → Lost/No Response
Per lead
Source, contact info, date captured, follow-up owner, status, reason for inquiry.
Conversion
When a lead books, it creates the patient card in the Care Pipeline — link the records, don't re-enter data.

9Reports NEW

Donna: "all this information that is collected in the background, if we want to run a report, we can run a report." Build reporting on the data already captured.

  • Patients by source (KPI), VOB pass rate, VA throughput/workload.
  • Lead → booked conversion rate, lead source performance, average time-to-contact.
  • Date-range selector + export.

10Auto-intake & VOB automation (backend) NEW

The highest-volume trigger is booking notifications by email/text (Headway, Grow Therapy, ZocDoc, Klarity, Google) — not phone. Build this first as a Make.com scenario that parses the notification and auto-creates an Onboarding card. This runs independently of the portal backend and can go live on ClickUp in the interim.

What "done" looks likeA booking arrives → card auto-created at Onboarding with name, DOB, contact, insurance (if provided), appointment, and source tagged → intake forms auto-sent via Optimantra portal → VOB auto-runs and writes result back to the card → if all good, ready for the VA; if not, flagged.
  • Each platform formats emails/texts differently — one parse rule per platform per channel. Prefer a native webhook/API where a platform offers one.
  • Map captured insurance fields (member ID, payer, group, subscriber DOB) to the Optimantra fields Eligible reads from.
  • Exception routing — flag to a VA only when: intake not completed in window, VOB failed/incomplete, self-pay card-on-file needed, or card stale past threshold (start 48h). Everything else moves with zero touch.
Confirm before building the triggerGet in writing from Optimantra support whether Eligible auto-runs on profile save or needs a manual "run eligibility" click even with the integration active — this decides whether VOB is fully hands-off.

11Phone & website chatbot (later phases) NEW

Secondary/later channels, but design their data capture to feed the same pipeline now so nothing is retrofitted later.

Phone intake — two paths to quote

  • Option A — vendor (e.g. Cevi.ai / similar): AI receptionist that connects to Optimantra. Faster, recurring fee, less control.
  • Option B — custom: telephony (Twilio) + conversational AI + Optimantra API write. More control, larger upfront build. There's also Donna's existing AI "Sunny/Q" to research as a possible reuse.
  • Deliverable: quote Option B time/cost and give a short Option A evaluation so Donna can compare.

Website chatbot with live handoff

  • Answers common questions (services, insurance accepted, telehealth vs. in-office, self-pay rates) and captures lead info.
  • Business hours: live handoff to a VA. After hours: capture + auto-reply + queue for next business day — no dead ends.
  • Captured leads route into the Lead CRM at the New Lead stage (not straight to Onboarding).
