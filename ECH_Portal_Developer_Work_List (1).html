7. Automatic Patient Intake (the Make.com webhook) 2 items 2 need work

1What the client asked for

The client's exact words: "A webhook endpoint (e.g. POST /api/patients/intake) that can receive new-patient data automatically from Make.com - this is the one piece the prototype structurally cannot do, and it's the main reason this needs to move off the artifact."

2What the portal does right now

A real POST request was sent to /api/patients/intake. It came back 404 Not Found with a plain HTML page. Not 401 (protected). Not 405 (wrong method). 404 - the route simply is not there. No patient card was created. The patient count stayed at 17.

In plain English: the single feature the client paid to move off the prototype for has not been built. Without it, someone still types in every patient by hand, which is the exact problem this app was meant to solve.

Important - this is NOT Optimantra work and must not be pushed to Phase 2. The bookings come from ZocDoc, Klarity, Headway, Grow Therapy and Google. They arrive as emails, Make.com reads those emails, and Make.com sends the details to this webhook. Optimantra is not involved anywhere in that chain. The client's brief describes exactly this route. Build it now.

3What to do
  1. 1. Build POST /api/patients/intake on the Railway backend (the front end on Vercel is not where this lives).
  2. 2. Protect it with a secret key sent in a header, for example X-API-Key. Any request without the right key gets 401. Do not use a login for this - Make.com cannot log in.
